# 翻斗卸料、土方去向与计量

## 直接验证

单独打开 `Assets/Robotics/zx200_description/Demos/SoilCutting/Demo 2/ZX200SoilDemo.unity`。
不要与原场景同时运行，以免出现重复设备、相机或地面。

1. Play 后等待设备稳定，斗量应为零。
2. 短按 F 降低动臂，看到斗量增加后停止；R 抬升，使斗尖离开土面。
3. Q 回转约 45 度，将斗尖移到右前方青色接收平台上方。
4. H 打开铲斗，达到卸料角度并保持 0.25 秒后，观察土流、斗量下降和接收量增加。
5. 中途用 Y 收斗或移出平台，卸料应暂停；无接收区时土仍保留在斗内。
6. Backspace 同时恢复土区、同一土区的铲斗库存和对应的接收记录。

已测试的关节操作：稳定后以 +10 度/秒降低动臂，斗量超过 0.02 m³ 后，
抬臂约 15 度，回转 -45 度，再以 -15 度/秒打开铲斗直至卸空。
这是测试所用操作序列，不是新增的自动作业功能。实际手动操作以斗尖位置和计量反馈为准。

菜单 `Tools > ZX200 > Soil > Create Independent Unloading Demo Scene`
也可另建独立演示。已存在的切削 demo 和 Cesium 场景不自动添加卸料组件。

## 控制与计量

- `BucketSoilCutter` 仍拥有斗内库存。`TransferTo` 只扣除接收区实际接受的量。
- `BucketSoilUnloader` 读取真实斗口朝向。斗口与竖直向下夹角不大于 65 度时进入准备状态，
  超过 78 度退出；有效接收区内停留 0.25 秒后，以默认 0.15 m³/s 转移。
- `SoilReceivingZone` 指定接收范围、容量与土层上限。满载、路径受阻、位置不符时不接收。
- 接收网格是等体积平整土层，土流是纯显示线条，不产生散落颗粒或额外刚体。
- `VolumeM3` / `MassKg` 是接收区总量；`Records` 提供每次转移的仿真时间、来源铲斗、
  来源土区、体积与质量。记录保存在当前运行会话内，尚未写入外部文件或数据库。
- `DeliveredVolumeM3` / `DeliveredMassKg` 是铲斗本轮累计卸料量。
- 土方按原状体积计量，密度在本轮首次挖入时固定，默认 1600 kg/m³；未加入松散系数。
  质量用于计量显示，尚未把可变土载荷加入 ArticulationBody 动力学。
- 守恒关系：同一土区挖出量 = 该土区各斗剩余量 + 各接收区来自该土区的累计接收量。
  重置会处理停用的组件，且保留接收区内来自其他土区的贡献。

接入车厢时，在车厢底部建立单位缩放、竖直朝上的接收节点，配置实际内宽/内长和容量，
赋予土壤材质，再填入铲斗卸料组件的 `receivers`。底板和侧壁仍用实体 Collider。
接收区支持平移与绕竖直轴旋转；倾斜车厢、非竖直重力、颗粒堆积和二次挖掘接收土层不在本版范围。
一次作业中保持土区引用、密度基准、接收区尺寸和接收组件生命周期稳定；需要换源或删除对象时先复位。

## 验证范围

Unity 6000.5.10f1，在独立验证工程执行 EditMode 与 PlayMode 测试；结果文件与截图随本目录提供。
最终结果：92 项 EditMode 与 6 项 PlayMode 全部通过。独立审查发现的斗尖内嵌障碍物漏检已增加重叠检测修复，并有失败/通过回归验证。
真实关节试验挖出并接收约 0.263582 m³，斗内归零，对应默认密度下约 421.73 kg。
涵盖容量限额、逐步卸料、角度滞回、暂停/重新进入、遮挡、错误时间参数、多接收区、
共享土区重置、不同土区互不影响，以及独立网格体积积分。

本次没有重新导出 Web，也没有修改 `Assets/Scenes/sence_test.unity`。
