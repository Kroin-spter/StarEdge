# 预置施工地形、紧凑待机和按土量收斗实施方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. 本文是方案，未授权以本轮请求直接修改运行代码。

**Goal:** sence_test 在播放前显示正确的施工土带和紧凑设备姿态，播放时无需重新扫描坡面；挖掘根据实际进斗量提前收斗，携土右转时斗杆更紧凑、斗口更接近水平。

**Architecture:** 将施工区生成拆为编辑器烘焙与运行时加载；保留独立、可复位的可挖 Terrain 副本。将停放、切入和携土姿态分开，以斗量、进斗速度、实际斗口方向和碰撞净空共同约束动作。沿用现有自动任务、土量账本和人工接管机制。

**Tech Stack:** Unity 6000.5.10f1、ArticulationBody、Unity Terrain、Cesium for Unity、Unity Test Framework。

## 全局约束

- 以 `Assets/Scenes/sence_test.unity` 为交付场景。
- 本轮只写方案；下列参数是调试起点和验收目标，不代表已经测得或已实现。
- 不通过设备整体平移、瞬移铲斗、关闭碰撞或伪造土量实现动作。
- 手动模式保持履带可驾驶；自动挖掘期间固定底盘，人工接管恢复原配置。
- 运行时挖掘修改 Terrain 副本，不污染烘焙资源；复位恢复初始土层。

## 一、当前问题与代码依据

1. `Zx200DigController.workReadyPose` 既用于待机，又被自动换点和复位复用。只把该姿态改紧，会同时改变切入路径和切削器启动条件。必须区分停放和挖掘准备。
2. `CesiumMoundSite` 在播放时等待地图碰撞体，检查支撑稳定性，搜索坡面、采样高程、生成土层和支撑面，之后才设置 `IsReady`。这解释了每次 Play 都有准备过程。
3. `DeformableSoilTerrain.Initialize` 已克隆 TerrainData，因此已有保护源资源的基础；烘焙还必须持久化实际不可挖地面高度，不能只保存含土的顶面。
4. `FillBucket` 已有初始收斗，但仍按固定阶段推进。当容量到顶而斗未闭合时，进入 `FinishFullBucketCurl`。
5. `FinishFullBucketCurl` 逐次调整大臂，等斗齿高于土面约 0.12m 后才完成闭斗。用户看到的“动不了、向上挪、然后收斗”与此顺序一致。
6. `RaiseToDumpClearance` 当前携土斗杆目标为 80°，铲斗目标来自 `curlPose.bucket - 10°`。这是相对关节角，不等同于斗口在世界空间水平。
7. 自动任务在非卸料阶段关闭卸料组件。因此“斗内土没减少”不能证明姿态真的能保土；需要独立测量姿态和可保留容量。

## 二、目标表现

打开场景：坡面贴土带、矿车和挖掘机均已就位，工作装置向内收拢，斗齿离地离坡。

按 Play：初始化本地土层副本与物理状态；无需重复坡面扫描。背景 Cesium 可以继续加载，施工区不因其等待而无法开始。

按 P：从停放姿态平滑进入准备姿态，接触泥土后持续收斗；进斗越快，越早减小斗杆推进并增加收斗比例。

接近目标量：以收斗为主，配合适量抬臂，完成闭斗并退出切面；不要把“满斗卡停”作为正常阶段触发条件。

携土右转：在挖掘方向先形成紧凑携土姿态，再平滑右转；斗杆内收，斗口朝上且接近水平，到车厢后再适量伸展卸料。

## 三、初始姿态：单独设计停放姿态

### 3.1 拆分用途

| 姿态 | 用途 | 设计原则 |
|---|---|---|
| parkedPose（新增） | 打开场景、刚进入 Play、复位结束 | 紧凑、安全、斗齿离地，直观看不到穿模 |
| workReadyPose（保留） | 每斗切削前定位 | 保证接近路径可达，不承担展示停放职责 |
| approachPose（保留） | 从准备位置接近土面 | 降低不必要抬臂，根据切面位置决定接触点 |
| carryPose（新增独立配置） | 完成切削后及右转 | 斗杆紧凑、斗口接近水平、足够回转净空 |
| dumpPose（保留并核对） | 车厢上方卸料 | 从携土姿态安全展开，到位后开斗 |

不要继续从 `curlPose` 减一个固定角度推算携土铲斗姿态；切削终态和保土状态应独立配置。

### 3.2 确定初始角度的方法

1. 读取实际关节轴、上下限、斗口标定方向和碰撞体；校验“增加角度”在本模型上对应的运动方向。
2. 在当前姿态附近搜索候选：斗杆向收回方向增加约 5～15°的收拢量；大臂配合降低或回收，铲斗向内闭合。
3. 用关节链正向运动学预测整个装置位置，筛掉超限、靠近驾驶室、碰坡或碰地候选。
4. 按斗齿离坡、铲斗离机身和整体伸出量选择紧凑候选；在实际物理系统中运行到稳定，再保存最终角度。
5. 编辑器预览与运行时使用同一姿态定义。只改 drive.target 不足以保证编辑器模型立即到位，需要同步可视关节姿态，并确保首次物理初始化不会弹回旧姿态。

初步安全目标：斗齿离地 0.4～0.8m；铲斗与坡面最近距离至少 0.5m；非接触机械部件保留约 0.15～0.25m 净空。最终以模型尺寸与实际几何结果确定，不能仅检查斗尖一个点。

### 3.3 启动逻辑

原本切削器依赖到达 `workReadyPose` 才解锁。如果停放姿态独立后仍等待此条件，可能导致新的启动死锁。

将“资源与关节引用有效”与“已到切削准备姿态”拆开：前者允许自动任务开始，后者只在完成准备动作后允许切削。切削过程中不得因偏离准备姿态重新锁住。

停放→准备、准备→接触全程检查净空。只在编辑器预置或初次物理初始化时设置初值，正常动作走关节驱动，不在 Play 后把已运动设备硬切回停放姿态。

## 四、施工 Terrain：编辑器烘焙，运行时直接加载

### 4.1 明确静态资源的含义

用户要的是把土坡提前保存到项目，在场景里直接看到。推荐本地持久化施工区，不把“勾选 Static”当作解决办法。可挖土层仍需运行时变形。

Cesium 场景对象是瓦片加载入口，保存场景不等于保存所有瓦片。局部 Terrain 烘焙后，施工区启动可以不依赖瓦片；如果还要求整个背景地图完全不出现逐块加载，需要另做背景地图离线资源或选定区域静态网格化，不应与本轮土区烘焙混为一项。

### 4.2 烘焙内容

新增施工区数据资源，保存：

- 含初始土带的 TerrainData，尺寸、分辨率、原点和材质层。
- 未加土的基础地面高程与可挖掩码，用于限制切削深度、计算初始可挖量与复位。
- 土带贴坡厚度、边缘过渡、坡向和可用挖点。
- 挖掘机与矿车的初始位置、朝向、地面支撑信息。
- Cesium 替换区域边界，地理参考原点/方向/比例及源数据标识。
- 资源格式版本、生成参数摘要、场景布局版本与完整性校验信息。
- 持久化纹理与 TerrainLayer 引用，禁止引用会随瓦片销毁的运行时临时纹理。

建议资源目录：`Assets/ConstructionSite/Baked/SenceTest/`。所有资源带 `.meta`，引用使用 Unity 资源引用，不能写开发机绝对路径。

### 4.3 编辑器烘焙流程

1. 通过显式菜单“烘焙当前施工区”触发，在编辑器中加载覆盖施工区的地图。
2. 确认采样范围完整、地形稳定，再执行已有坡面采样与土带生成逻辑。
3. 验证履带支撑、矿车四角支撑、土带连续性、初始姿态与回转空间。
4. 输出临时资源并完成校验；全部通过后才更新正式资源及场景引用，失败时保留上次有效资源。
5. 保存场景，让 Terrain 和设备在非 Play 状态下可见；提供“验证已烘焙施工区”检查按钮。

现有 Terrain 用高度场表示坡面，本轮保持选定的可表示斜坡。垂直墙、悬挑和向内掏洞需要体素或网格方案，不通过旋转 Terrain 来模拟。当前可挖组件明确要求世界旋转为零、缩放为一。

### 4.4 运行时加载流程

读取烘焙资源→校验版本与地理参考→克隆可变 TerrainData→绑定 TerrainCollider→恢复基础地面高程与掩码→初始化土量→初始化设备姿态→物理稳定后就绪。

默认使用烘焙模式。资源缺失、地理参考不匹配或数据损坏时，明确显示“需要重新烘焙”的原因；不得悄悄退回扫描并再次长时间卡在就绪阶段。现有动态生成作为明确选择的开发模式保留。

目标：在当前机器、编辑器已完成脚本编译和资源导入的条件下，Play 后施工区就绪通常在 1 秒内，验收上限先定 2 秒；实测需记录中位数和最大值。编辑器编译、包导入与背景全图加载时间不计入这个局部初始化指标。

### 4.5 地图遮挡和重复碰撞

本地 Terrain 覆盖土带、两车支撑区和两者之间的工作空间。`ConstructionSiteMapClip` 在本地资源加载后立即获得有效替换边界，对已加载及后来新建的 Cesium 瓦片都执行同一裁剪。

裁剪必须同时处理渲染和碰撞，不能只禁用地图碰撞后让原坡面继续遮住挖坑。保存地图原网格恢复信息；卸载、重载时不能重复裁剪已经处理的网格。局部支撑由本地 Terrain 提供，背景瓦片加载不能把设备顶起或盖回挖坑。

### 4.6 验收

- 未进入 Play 时即可看见贴坡土带和正确设备位置。
- Cesium 数据服务不可用时，本地施工区仍可就绪并完成局部挖掘；背景缺失与局部功能分别报告。
- 连续启动 5 次，记录初始化时间，不再执行运行时坡面搜索和采样。
- 完成多斗后退出 Play，烘焙资源内容及版本控制状态不因运行改变。
- 挖坑后加载新瓦片，不出现地形遮盖、重复碰撞或设备抬升。

## 五、根据土量提前收斗

### 5.1 原因与改造目标

当前“早期固定收斗 + 容量到顶后的脱坡闭斗”仍允许斗杆在铲斗尚未闭合时先把剩余容量吃完。穿入保护随后停止继续切削，才触发补救。

新逻辑以实际进斗量为反馈，让斗杆推进逐步让位给收斗；保留满斗和穿入保护，但让它们成为异常兜底。

### 5.2 反馈量

每个物理帧读取：实际斗量 V、有效容量 C、平滑进斗速率 q、铲斗距离安全闭合姿态的剩余角度、实际关节速度、斗齿轨迹及进度受限状态。

使用 0.2～0.4 秒滑动窗口估计 q，忽略异常负变化和极小容量。闭斗时间来自剩余角度和可实现的角速度，设置最小速度与最大预测时间，避免除零和关节卡停造成无穷预测。

预测关系：`预计闭斗时体积 = V + q × 预计闭斗时间`。预测值接近有效容量的 85%～90% 时，即使当前量尚未达到固定阈值，也优先收斗。

### 5.3 初始调参表

以下区间是起点，要结合当前约 0.30m³ 有效容量与实际土层厚度调试。

| 实际满度 V/C | 动作分配 | 目的 |
|---|---|---|
| 0～25% | 斗齿入土后缓慢收斗，小臂继续切入 | 保持连续接触，不让铲斗保持固定 |
| 25～55% | 增加收斗速度，逐渐降低斗杆推进 | 提前积累闭斗角度 |
| 55～75% | 收斗主导，适量抬臂和回收斗杆 | 减少继续吃土并准备离开切面 |
| 75～90% | 达到安全保土姿态后转入脱坡携土 | 保留容量余量，减少满斗卡死 |
| 即将触发容量/穿入限制 | 取消继续向实体推进，按净空协同退出 | 异常兜底并记录原因 |

不要直接把所有目标改为固定 90% 满斗：薄层与最后一斗可能达不到。满足最小有效斗量、切削量持续下降且闭斗安全时，可以结束该斗；确实无土才进入换点流程。

### 5.4 动作生成

将固定时间片收斗改为连续目标更新；收斗权重随满度和预测量单调增加，并对切换设滞回。关节目标速度和加速度限幅，阶段切换继承当前角度与速度，避免每帧重启整段插值。

示意控制次序：

```text
读取真实斗量、关节姿态、土面和接触信息
更新进斗速率与闭斗时间预测
根据当前/预测满度提高收斗权重，降低继续切入速度
求解满足关节限位及碰撞净空的短时目标
若继续收斗会撞入未切除土体，减少推进并小幅协同抬臂
若已达到有效斗量且安全闭斗，进入携土准备
若存在持续无进展，执行受限恢复或报告故障
```

不得为了闭斗而把不存在容量的土从地形中扣除。所有地形移除仍受剩余容量约束；遇实体阻碍必须修改运动路径。

### 5.5 卡停与验收

当切削中 0.35～0.5 秒内关节/斗齿/土量均无有效进展时，进入诊断和小幅恢复，而非持续等待总超时。阈值要排除正常缓启动和接近零速换向。

正常新鲜土层前 3 斗不应触发“满斗后先抬升再闭斗”恢复路径；达到约 55% 满度时应已存在明显收斗进展。连续僵停目标小于 0.5 秒，任何超过该值的停顿都记录姿态、斗量、容量和保护状态。

必须检查“真实土量守恒、未穿过未切土层、没有通过整体平移实现上抬”，再评价动作观感。

## 六、右转携土：小臂进一步收回，斗口更平

### 6.1 用世界方向定义斗口水平

标定实际斗口平面，验证 `BucketSoilUnloader.openingNormalLocal` 与模型一致。斗口水平且朝上应表现为斗口法线与世界向上方向接近。

定义 `mouthTilt = angle(worldMouthNormal, -gravity.normalized)`。携土稳定阶段初始目标 0～15°；进入回转的上限先设 20°。同时检查斗口横向倾斜，不能只从侧视图判断。

目标是“斗口朝上能保住土”，不是要求斗底、斗齿或某个关节角为零。

### 6.2 携土姿态求解

斗杆从当前 80°附近向收回方向继续尝试约 5～12°。在关节限位、模型自碰撞、重心附近净空和车厢可达性都满足后，才保存最终值。

大臂根据斗齿高度配合调整；铲斗根据大臂、小臂的实际姿态补偿世界斗口方向。利用现有关节轴计算候选斗口方向，对铲斗的一维允许角度范围进行搜索，再选最接近目标且净空合格的角度。

多解时优先：无碰撞→满足保土→满足地面净空→工作装置紧凑→角度变化较小。不可达时保持最近安全姿态并报告约束原因，不强行压到角度上限。

### 6.3 回转和卸料衔接

满斗退出切面后连续形成紧凑姿态；只有斗口和回转扫掠空间合格才开始向右回转。

回转采用限速、限加速度的平滑曲线，起止均缓变。初始参考最大角速度 15～25°/秒、角加速度 10～20°/秒²；最终按设备惯性和约 90°工作角实测整定。

先保持当前矿车位置，验证紧凑携土后是否仍可安全展开到车厢。若必须移动矿车，只在已有支撑区域内做小范围调整，并重新烘焙布局。

到车厢方向后在车厢外上方适量展开，完成落点和高度确认后再开斗。不得用过早伸臂来弥补携土阶段收得更紧，也不得在开斗后继续做明显回转修正。

### 6.4 保土验证

将几何可保留容量的计算与“是否发射卸料土粒”分离。即使自动状态禁止正式卸料，也必须能根据斗口方向和土面计算理论可保留量。

携土姿态要求理论可保留量不小于当前载荷；若不满足，先修正姿态，不能以卸料组件处于禁用状态证明没有撒土。完整的加速度导致土粒抛出模拟不作为本轮承诺，但回转速度必须限制并明确该物理近似。

## 九、完成标准

| 需求 | 通过依据 |
|---|---|
| 初始收小且不穿模 | 编辑器和 Play 初始姿态一致；斗齿、斗壳、斗杆与坡面/机身均有净空 |
| 不再每次生成施工土区 | 本地资源加载；不执行运行时地图采样；5 次启动时间有记录 |
| 根据料量提前收斗 | 正常装料中连续收斗；前 3 斗不依赖满斗卡停后再闭斗的恢复路径 |
| 右转时更紧凑且斗口更平 | 相较当前伸出量缩小；稳定携土倾角目标≤15°，回转阶段目标≤20° |
| 持续自动挖掘 | 至少 3 斗真实挖掘、回转、装车、返回；地形、斗内、空中与车厢量可核对 |
| 操作恢复可靠 | Esc 接管释放控制和临时锁定；Backspace 恢复初始土层及停放状态 |

数值阈值经几何与物理验证后允许合理调整，但必须保留对应测量结果与原因；不能以改变验收阈值掩盖视觉问题。
