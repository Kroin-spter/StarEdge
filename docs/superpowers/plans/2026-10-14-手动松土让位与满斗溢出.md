# 手动松土让位与满斗溢出 Implementation Plan

**Goal:** 手动有效切削能推进，满斗继续切土并守恒侧落，适度扩大经过几何检查的斗内容量。

**Architecture:** 分离切削预算和收集容量；保留原自动流程。手动斗壳限位在刃口接触可挖土、输入属于有效切削时允许有限软土让位，不允许无限深入和底层穿透。

**Constraints:** 不改变地图、矿卡、串口。用户 ProjectSettings 和临时 TerrainData 保留。当前分支 fix/manual-soil-yield-overflow，独立 manual-acceptance-5JEDMw 副本运行 Unity。

## Tasks

- [x] 在 BladeCollectionTests 添加小容量满斗仍切削、侧落有真实传输且总量守恒测试，先运行失败再修改 BucketSoilCutter：切削预算由扫掠行程决定，collected=min(removed*efficiency,available)，其余交给现有土方传输。
- [x] 在 SoilResistanceTests 添加接触有效刃口时可受控推进、未接触刃口仍保护斗背的测试。移除手动满斗硬锁，斗壳允许有限切削接触余量；不放宽土层底部保护或自动轨迹。
- [x] 检查 ZX200 真实斗壳与 BucketSoilFill 几何，保守扩大腔体标定，场景容量与几何一致；测试进土、显示、卸料守恒。
- [x] EditMode 回归相关切削/约束/土方传输测试；实际场景检查不同手动角度、退出和自动连续三斗，记录残留限制，不以增大超时掩盖卡死。

## 排查与实施记录

- 复现：满斗新增移除量为 0；浅接触的 0.1° 请求被限到约 0.0057°。驱动已有 0.5° 支撑偏移时，继续切削请求被错误拉回 0.12°。
- 手动切削预算改用实际刃口宽度、行程和可挖深度；斗容量只限制收集量，所有其余移除量进入原有土方传输。
- 仅放宽刃口接触余量仍不能解决 65° 斗壳先接触。补充手动持续压入时的局部松土位移：只用实际斗壳接触点，每步限制深度 4cm、合计速率 0.06m³/s、最多 8 个小片区，不增加进斗量，保留原 Terrain 的 floor/holes/边界约束。
- 手动限速保留 drive target 的重力支撑偏移；自动仍使用原限速和满斗逻辑。
- 场景容量从 0.303886 调至 0.335874m³；腔体半宽从 0.38 到 0.42m，截面不变。已有真实斗壳相交测试通过，新增 0.33m³ 显示体积测试先失败后通过。
- 更新旧测试的守恒账目：满斗侧落也属于移除土量，卸料步增量不能与包含此前侧落的累计排出量混淆。
- 增加整轮自动任务的控制权判断，自动阶段间等待不再误用手动切削策略。
- 扩容回归暴露少量侧落土仍在移动导致卸料超时：增加实际车厢收土证明，只有本斗至少 99.5%（且差额不超过 1L）已进车厢时才允许不等待这些微量颗粒。它们仍留在传输账目中，未删除、未算作装车；原动作轨迹不变。
- 手动 65° 测试明确采用开斗切入输入，不再把继续关闭一个已闭合的斗口当作合理进土动作。单纯继续收斗的历史试验进土很低，不能宣称任意姿态任意方向都可满斗。
- 审查发现软接触余量适用范围过宽，已限制到实际近土、向内、非侧擦且高于底层的采样点；2.5cm 预接触余量用于启动压土，不是无限穿透许可。
- 初步实际测试：三斗装车 0.69070m³；手动完整切削/收斗/退出最后保留 0.30530m³（约 91% 容量）；逐采样点收紧后的最终回归另行记录。
