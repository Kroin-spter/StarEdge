# ZX200 自动挖掘回转卸料修复设计

## 目标

修复自主挖掘只完成切土、没有可靠回转卸料的问题，使场景中可观察到完整的“挖掘—抬升—回转—卸料—返回”流程，并以车厢实际接收土量作为卸料成功依据。

## 现状与风险

自主状态机已有回转和卸料阶段，但抬升阶段使用固定高位姿态，随后以斗尖高度和车厢实体碰撞体检查净空；检查失败会在回转前停止。状态转换目前没有独立的画面提示，因而玩家只看到切土时，无法从游戏画面判断流程停在哪一阶段。

## 方案

1. 抬升准备姿态从设备当前姿态和关节限位推导，不再依赖单一固定动臂角。抬升后检查斗尖相对车厢最高实体的净空；不满足时进入清楚的故障状态，不允许带斗回转或开斗。
2. 保留基于接收区几何位置计算回转角的方式。回转到位后再验证斗尖位于车厢接收区上方且有净空，随后执行开斗；只有接收区实收土量达到阈值才认定卸料完成。
3. 在游戏画面展示自主阶段、状态说明/故障原因、完成斗数、任务交付量与当前斗量；状态转换同步写入 Unity 日志，方便定位运行停止点。
4. 施工车辆停车位置保持与土区的碰撞净距，同时避免超出设备可达范围。以 EditMode 测试约束停车偏移，以 PlayMode 测试验证真实场景中至少完成一斗且接收区土量增加。

## 失败处理

任何阶段超时、不可达、净空不足、空挖、或车厢未实际接收土量时，自动流程停止并保留明确的状态与故障原因。人工接管与复位行为保持现有语义，不回滚已发生的物理土量变化（复位仍按现有明确复位功能执行）。

## 验收标准

- EditMode 测试通过，验证停车位满足土区净距且位于挖掘机工作半径内。
- PlayMode 测试在 `Assets/Scenes/sence_test.unity` 中确认流程经过 `SwingToTruck`、`Dump`、`ConfirmDump`，最终车厢实际土量增加、铲斗残土和空中土流低于阈值，并完成返回。
- 游戏画面能持续显示自主阶段；若流程失败，画面和日志均显示具体故障原因。
- Git 改动不包含 Unity 临时缓存；提交说明使用中文，作者名使用 `shenkai`；不推送远端。

## 验证边界

优先使用项目现有 Unity Test Framework 自动化测试。若 Unity Editor/PlayMode 因运行环境或 Cesium 初始化限制无法执行，应记录实际命令、测试结果与未验证原因，不以静态检查替代运行成功的声明。
